# Studio — lessons, decks and mind maps from your own sources

Studio is the "notebook" half of the app: pick a handful of documents and turn them into something
you can teach from. It is deliberately close to the NotebookLM workflow — sources in, artifact out —
but it runs on the same local database as everything else, and it produces a useful artifact with no
model configured.

```
sources ──▶ lesson   (objectives, concepts, terms, example, quiz, flashcards)
        ├─▶ deck    (title, agenda, one slide per source, takeaways, sources)
        └─▶ mindmap (one branch per source, key points underneath)
```

## Choosing sources

`POST /api/v1/studio/generate` takes exactly one of:

| Field | Meaning |
| --- | --- |
| `documentIds` | The explicit set picked in the Studio UI |
| `collectionId` | Resolve a saved collection to its documents |
| `query` | Hybrid search, top results become the sources |

`limit` caps the set (default 8, max 25). Fewer, focused sources make a better lesson; a wide set is
better for a survey deck.

The picker loads the whole library (200 documents per page, up to 2,000), can narrow it by shelf, and
searches titles and source ids. The “Showing N of M documents” line makes it obvious when a filter is
hiding the file you want; anything not imported yet goes through **Import** first.

## The lesson

A deterministic lesson contains:

1. **Learning objectives** — one per leading source.
2. **Core concepts** — a subsection per source, with the highest-signal sentences and a `[n]`.
3. **Key terms** — the most frequent domain terms with the sentence that defines them.
4. **Worked example** — a passage that reads like a procedure or case.
5. **Check your understanding** — four question/answer pairs, each tied to a source.
6. **Flashcards** — term → definition.
7. **Sources** — the numbered list the citations resolve to.

Sentence selection filters out tables of contents, page markers and dot leaders before ranking, so a
PDF manual does not turn into a table of contents.

## The deck

A deterministic deck is 6–10 slides: a title slide, an agenda, one slide per source (four bullets),
key takeaways and a sources slide. Speaker notes carry the source number and path.

Two exports are built in, both generated in the browser from the stored slides:

- **Marp Markdown** — `marp: true`, one `---` between slides, notes as HTML comments. Works with
  Marp, Obsidian Slides and most Markdown deck tools.
- **Standalone HTML** — one file with inline CSS and arrow-key navigation, no external assets.

The in-app presenter supports arrow keys, `Esc`, a notes toggle and a full-screen mode.

## The mind map

A mind map is a two-level tree: the root is the topic, each branch is a source (or, for a single
document, one of its headings), and the leaves are the highest-signal sentences under that branch,
each carrying the `[n]` of the source it came from.

- **Several sources** — one branch per document, up to seven, with up to four leaves each.
- **One document** — branches come from the chunk headings, so a manual becomes its own structure.
- **In the app** — zoom controls and hover text with the full sentence; the layout is a deterministic
  horizontal tree, so the same artifact always draws the same shape.
- **Export** — a self-contained SVG with no external fonts or scripts, sized to its content.

## With a model

Studio is **model-first**. When a model is configured, every artifact is generated by it by default
(`useLlm` defaults to true):

- the lesson comes back as Markdown and replaces the deterministic one;
- the deck and the mind map come back as JSON and replace their deterministic versions;
- the request asks for up to 4,000 output tokens and allows 180 s, enough for a full lesson or a
  ten-slide deck on a free model.

The local generator runs only when the model cannot be used: no provider configured, the call fails
or times out, or the response is empty/invalid JSON. Generation therefore never fails because of the
model — it just falls back and the artifact is marked `no model`. Pass `useLlm: false` (CLI
`--no-llm`) to force the deterministic path.

Studio can use a different model from chat: set `SB_STUDIO_MODEL` (or the matching `.env` entry) to a
model that is good at writing. This matters with reasoning models, which sometimes spend the whole
token budget thinking and return no article. The default remains `SB_AI_CHAT_MODEL`.

## API

| Method | Path | Notes |
| --- | --- | --- |
| `POST` | `/api/v1/studio/generate` | `{ kind: "lesson"\|"slides"\|"mindmap", documentIds? , collectionId?, query?, limit?, maxSlides?, lang?, useLlm?, title? }` |
| `GET` | `/api/v1/studio/artifacts` | `?kind=lesson|slides|mindmap&limit=N` |
| `GET` | `/api/v1/studio/artifacts/:id` | One artifact, slides/mind map and citations included |
| `DELETE` | `/api/v1/studio/artifacts/:id` | Delete the artifact, keep the sources |

## CLI

```bash
npm run cli -- studio lesson --filter 01_Guidelines --limit 6
npm run cli -- studio slides --docs doc_a,doc_b --max-slides 12 --lang vi
npm run cli -- studio mindmap --filter 01_Guidelines --limit 5
npm run cli -- studio list
npm run cli -- studio show art_…
npm run cli -- studio export art_… --out deck.md      # .svg for a mind map
```

## Limits

- Lessons, decks and mind maps are extractive without a model: they select, order and label, they do
  not rewrite.
- A deck is a summary of the selected sources, not a designed visual template; the HTML export is
  intentionally plain so it stays editable.
- Source discovery is capped at 25 documents per artifact; that is a context window decision, not a
  storage one.
